请阅读当前 Vue 3 + TypeScript 交易客户端代码，做一轮“顶部栏、搜索、刷新、页面动作”的交互精简与成熟化改造。目标不是新增复杂功能，而是让页面更符合真实交易/信息系统使用习惯，为下一步开发交易和委托逻辑打好基础。

## 本轮重点

当前很多页面都在 `AppShell / TopBar` 顶部放了统一搜索框和两个按钮，导致功能重复、按钮语义不清、页面像模板化 PPT。请改成“全局工具栏 + 页面主任务”的结构。

## 1. TopBar / AppShell 调整

请修改 `TopBar.vue` 和相关 `AppShell` 传参逻辑，使顶部栏支持按页面配置：

* `showSearch?: boolean`
* `searchPlaceholder?: string`
* `showRefresh?: boolean`
* `refreshLabel?: string`
* `refreshing?: boolean`
* `lastUpdated?: string`
* `statusItems?: { label: string; value: string }[]`
* `actions` 插槽保留，但只放真正重要的页面级动作

顶部搜索不要每个页面都默认显示。建议：

* 首页：隐藏搜索，或只保留“跳转股票/委托”的轻量全局搜索。
* 行情页：可以显示搜索，但页面内已有 `StockSearchPanel`，顶部搜索应隐藏，避免重复。
* 交易页：隐藏顶部搜索，下单表单里的股票代码输入才是主搜索。
* 委托成交页：顶部可显示委托号/股票搜索。
* 资产页：隐藏顶部搜索。
* 提醒页：隐藏顶部搜索。
* 安全页：隐藏顶部搜索。

顶部右侧可以保留小状态信息，例如：

* 资金账号
* 行情：正常
* 交易通道：正常

不要让顶部每个页面都固定出现“搜索 + 两个按钮”。

## 2. 页面顶部按钮精简

请逐页清理当前页面顶部 actions：

* `DashboardView`：保留“新建委托”和“刷新本页”，移除没有实际意义的“导出”。
* `MarketView`：移除顶部“创建提醒 / 下载行情”，这些应放到股票详情或表格行内；顶部只保留“刷新行情”或自动刷新状态。
* `TradeView`：移除顶部“全部撤单 / 查看限价”。交易页主动作应在下单表单中完成；可以保留一个“查看委托”链接按钮。
* `OrdersView`：保留“批量撤单”和“刷新委托”；导出可以先隐藏，等数据稳定后再做。
* `AccountView`：保留“存款 / 取款”，但刷新资产应作为页面刷新，而不是资金卡和持仓卡各刷各的。
* `AlertsView`：保留“新增提醒”；“全部暂停”可以放在提醒列表卡片内部。
* `SettingsView`：移除顶部“保存”，因为交易密码和取款密码应各自有独立保存按钮；顶部可只保留“验证证书”。

## 3. 搜索区域精简

请改造 `StockSearchPanel.vue`：

当前“代码/名称 + 板块 + 刷新方式只读输入 + 今日/本周/本月/本季按钮 + 查询/重置”显得按钮过多。

请调整为：

* 第一行：代码或名称输入、板块选择、查询按钮、重置按钮。
* 第二行：轻量筛选 chip，例如 今日 / 本周 / 本月；不要使用大按钮。
* 移除“刷新方式”的只读 input。
* 刷新方式交给行情页顶部或行情表头处理。
* 输入框支持 Enter 查询。
* 如果后端暂不支持区间筛选，区间 chip 只影响 UI 状态，不要构造无效请求。

行情页不要同时存在顶部搜索和 `StockSearchPanel` 搜索，两者保留一个即可，优先保留页面内 `StockSearchPanel`。

## 4. 刷新逻辑统一

当前 `FundsSummary`、`HoldingsTable`、`MarketTable` 等组件各自有手动刷新按钮，体验上会让用户困惑：点击某个刷新只刷新一个板块，资产总览却不同步。

请按真实信息系统习惯改成“页面级刷新为主，局部刷新为辅”：

### 行情页

* 行情数据可以自动刷新。
* `MarketView` 顶部显示：`行情更新于 xx:xx（刚刚）`
* 提供一个页面级“刷新行情”按钮。
* 这个按钮应同时刷新行情表、当前股票详情、右侧市场脉动。
* 可以保留自动刷新开关：手动 / 自动 5 秒。
* 不要在每个行情子卡片都放单独刷新按钮。

### 首页 / 资产页

* 资金和持仓应被视为一个资产快照。
* 页面级按钮叫“刷新资产”。
* 点击后同时刷新资金和持仓。
* 移除 `FundsSummary` 和 `HoldingsTable` 卡片右上角各自的“手动刷新”，或者改成很弱的文本按钮，不作为主要入口。

实现方式尽量简单：

* 可以在父页面维护 `refreshKey`。
* 点击页面级刷新时 `refreshKey++`。
* `FundsSummary` 和 `HoldingsTable` 接收 `refreshKey` prop 并 watch 后重新请求。
* 不要引入复杂全局 store。

### 委托页

* 页面级按钮叫“刷新委托”。
* 刷新委托列表和成交回报。
* 撤单后自动刷新或更新本地状态。

### 设置页

* 不需要页面级刷新。
* 登录记录卡片内部可以有“刷新记录”小按钮。
* 证书卡片内部可以有“验证证书”按钮。

## 5. 组件层面的必要整理

请顺手处理几个会影响下一步交易/委托开发的问题：

1. `OrderListTable.vue`

   * 不要在组件内部写死 orders。
   * 改为通过 `items` props 传入。
   * 支持 `@cancel` 事件。
   * 支持空态。
   * 数字列右对齐，状态用状态标签。

2. `PriceTicker.vue`

   * 不要完全写死数据。
   * 支持 `items` props。
   * 没传 items 时再用 fallback 数据。
   * 支持点击股票 emit `select`。

3. `MarketTable.vue`

   * 增加选中行状态。
   * 增加操作列：买入、卖出、提醒。
   * emit `select`、`buy`、`sell`、`alert`。
   * 数字列右对齐。

4. `HoldingsTable.vue`

   * 支持父组件传入 `refreshKey`。
   * 可以增加行内操作：买入、卖出、详情。
   * 不要只作为静态展示表。

5. `FundsSummary.vue`

   * 支持父组件传入 `refreshKey`。
   * 移除或弱化内部手动刷新按钮。
   * 对外可以 `defineExpose({ refresh })`，但优先用 `refreshKey`，保持简单。

## 6. 视觉和文案细节

请统一以下文案：

* “总览”改为“首页”
* “下单”改为“交易”
* “委托”改为“委托成交”
* “账户”改为“资产”
* “设置”改为“安全”

刷新按钮文案不要都叫“手动刷新”，而要说明刷新对象：

* 刷新行情
* 刷新资产
* 刷新委托
* 刷新记录

空态文案要具体：

* 暂无行情数据，请输入股票代码或名称查询
* 暂无持仓
* 暂无委托记录
* 暂无成交回报

## 7. 不要做的事

* 不要引入大型 UI 框架。
* 不要引入复杂状态管理。
* 不要做真实撮合逻辑。
* 不要大改后端接口。
* 不要新增复杂图表。
* 不要把刷新逻辑做成 WebSocket。
* 不要为了统一而让所有页面都拥有相同顶部按钮。

## 验收标准

修改完成后应满足：

1. 每个页面顶部按钮都是当前页面真正需要的操作。
2. 顶部搜索不再每页重复出现。
3. 行情搜索只保留一个明确入口。
4. 刷新从“每个卡片各刷各的”改成“页面级刷新为主”。
5. 行情页、资产页、委托页都有明确更新时间。
6. 组件不再过度写死 mock 数据，方便下一步接交易/委托逻辑。
7. 页面看起来更像真实客户端，而不是统一模板套出来的 PPT。
8. TypeScript 不报错，现有后端接口仍能使用。
