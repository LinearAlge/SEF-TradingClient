## 1. 引言

### 1.1 编写目的

本测试报告为股票交易系统客户端子系统的产品测试报告，目的在于总结测试阶段对系统各功能模块的验证结果，评估系统是否达到《软件需求分析报告》和《系统设计报告》中预期的功能目标。

本报告的预期读者包括：项目指导教师、课程助教、项目组全体成员、系统开发与维护人员。

### 1.2 项目背景

本项目是浙江大学《软件工程基础课程》的大作业，要求实现一个完整的股票交易系统。本小组负责**交易客户端子系统**的开发。版本 v2.0 将后端从 Node.js 网关架构重构为 **Python FastAPI 统一后端**，便于与其他 Python 技术栈的小组进行联调集成。

### 1.4 系统简介

交易客户端子系统为投资者提供股票交易的终端界面。本版本采用以下架构：

- **前端**：Vue 3 + Vite + Vue Router + Pinia（TypeScript）
- **后端**：Python 3.11+ FastAPI 统一后端（端口 8000）
- **数据库**：SQLite（SQLAlchemy ORM）
- **Mock 服务**：内置于 FastAPI 路由中（`/api/v1/account`、`/api/v1/trade`、`/api/v1/info`、`/api/v1/admin`）
- **客户端 API**：`/api/client/*` 路由（认证、交易、行情、提醒等）

系统实现了实验大纲第四章的全部功能，包括：登录与证书管理、证券持仓查询、资金帐户查询、买入委托、卖出委托、撤单、交易结果显示、行情查询、密码修改、价格提醒。

**v2.0 重构重点变化：**
- 后端从 Node.js (CJS) 迁移到 Python FastAPI
- 新增服务端业务校验：资金冻结/解冻、持仓校验、涨跌停限制、账户关联校验
- API 响应新增 `code` 和 `message` 字段

### 1.5 测试对象——交易客户端子系统

测试对象为 FastAPI 后端的 **客户端 API 层**（`http://localhost:8000/api/client`），该层通过内部 Adapter 调用 Mock 路由，对返回数据进行映射处理后响应前端请求。

测试范围涵盖客户端 API 的全部端点，对应客户端的 10 个业务功能。

## 7. 对软件功能的结论

### 7.1 能力

经过 52 个自动化测试用例和手动 UI 验证，交易客户端子系统**已实现实验大纲第四章的全部功能要求**：

- **登录与证书管理**：支持密码登录、首次证书绑定（enroll）、证书挑战验证（verify）、换设备重绑（rebind）、客户端权限申请，错误密码和空参数均被正确拦截
- **证券持仓查询**：正确展示股票代码、名称、持有股数、加权平均成本、最新市价、盈亏金额及比例、可卖/冻结数量
- **资金帐户查询**：可用资金、冻结资金、证券市值、资产总值（等式 totalEquity = available + frozen + marketValue 校验通过），资金流水和证券流水记录完整
- **买入/卖出委托**：服务端实现了完整的业务校验链——涨跌停价格限制（TRADE_E05）、资金冻结与余额检查、持仓冻结与可用检查、数量合法性校验（TRADE_E06）、账户关联校验
- **撤单**：正确拒绝已成交/已撤单委托的重试撤单，撤单后自动解冻对应资金或持仓
- **交易结果显示**：委托列表字段完整，成交记录正确关联委托编号，状态枚举值全部符合定义
- **行情查询**：支持板块筛选、代码/名称搜索、单股详情（含公告）、批量报价、价格数据逻辑一致性验证，mapper 层将内部字符串价格正确转为数值类型
- **密码修改**：交易密码和取款密码独立管理，旧密码校验正确
- **价格提醒**：完整生命周期管理（新增→监控→暂停→恢复→删除），提醒状态流转正确

在压力测试中，系统在 100 并发委托提交场景下保持稳定运行，所有请求均成功返回。

### 7.2 限制

| 编号 | 限制项 | 影响范围 | 说明 |
|------|--------|---------|------|
| 1 | Mock 账户绑定 | 联调前 | 当前仅支持 FUND000001 ↔ SEC000001 的账户关联，其他账户组合返回未绑定 |
| 2 | 市场数据动态更新 | 测试稳定性 | `market_updater.py` 每 5 秒更新行情价格，导致涨跌停边界值在测试中波动 |
| 3 | 前端风控缺失 | 安全性 | 服务端已实现业务校验，但前端尚未同步实现本地风控（如买入前检查余额、卖出前检查持仓），用户可能在提交后才知道被拒 |
| 4 | 无真实认证 Token | 安全性 | 当前登录返回 mock token，未集成 JWT 签发和过期刷新机制 |
| 5 | WebSocket 未测试 | 功能性 | 后端提供 `/ws/orders` 实时推送端点，但未编写对应的自动化测试 |

### 7.3 改进建议

1. **联调适配**：将 AccountAdapter 中的硬编码 `FUND000001`/`SEC000001` 映射替换为动态查询
2. **前端风控同步**：在 Vue 层添加与后端一致的价格区间、资金充足性、持仓可用性校验，提升用户体验
3. **认证机制**：引入真实的 JWT 生成与验证，替换 mock token
4. **CI 集成**：将 `pytest tests_pytest/ -v` 加入 GitHub Actions，每次 push 自动运行
